# SPICE console screenshot adapter

Build with `native/tools/build-spice-screenshot.sh`, using the already verified local upstream SPICE prerequisites. Invoke `.local/bin/spice-screenshot SPICE_UNIX_SOCKET`. One stdout JSON result is emitted; diagnostics stay on stderr. A failure returns exit1 and an explicit `error`, never a successful empty image.

The adapter accepts the measured Darwin FIFO/IOSurface transport, display0 and BGRA top-row-first memory. It requires a fresh descriptor, checks generation liveness before and after an owned Metal copy, and captures only on a draw callback before acknowledging the producer. It does not capture the host screen or require a native VM window. No guest scale is guessed: coordinates are physical guest pixels and `guest_ui_scale` is null. The output includes a random frame ID, UTC and monotonic capture timestamps, dimensions, PNG byte length and base64 image.

Bounds: at most4096 per dimension and8,388,608 source pixels; PNG at most700KiB so base64 plus metadata fits the current1MiB worker protocol. Oversize is an explicit error, with no silent cropping or downscaling. A10second GLib deadline and500ms nonblocking output deadline apply; the parent must also impose a15second process deadline/kill-and-reap in case a GPU driver call stalls. Only one image/copy is retained. `internal_scanout_id` is host-internal generation metadata and must be stripped before remote/MCP responses; it is not a user permission or stable global display identity.

Actual fixture validation: `PATH=/opt/homebrew/bin:$PATH python3 native/tests/test-spice-screenshot.py --output .local/evidence/screenshot-UNIQUE.json`. The wrapper owns a corrected disposable Linux graphics VM, compares independently decoded images against Guest XWD geometry/orientation, checks two separate reconnect captures and an unavailable socket, then stops its VM. See [evidence](../../docs/evidence/spice-screenshot.md). No public distribution rights, macOS/Windows screenshot support, input authority, color-management accuracy or performance claim follows from this narrow adapter.
